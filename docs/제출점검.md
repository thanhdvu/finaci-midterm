## 가산 +5의 정확한 조건

W07 p26의 Vercel 예시는 **한 프로젝트의 웹 빌드(/)와 읽기 전용 data API(/api)**를 요구한다. 2026-10-29 https://flying-fjord-n1xr8rj-thuyanhdv-3408.vercel.app 의 웹과 API GET 200, 데이터 POST/PUT/DELETE 403을 확인했다. 학생은 프로젝트를 자신의 계정으로 수령했다고 확인했으므로 **Vercel 기술 조건 +5를 제안**한다. 본점 86 + 가산 5 = 잠정 91이며 실제 성적·가산 적용은 강사가 정한다. 주간 과제의 cache/두 번째 기기 가산은 이번 rubric에 더하지 않는다.

## 형식·내용의 남은 한계

- 수업의 표·원칙 카드·요소 분석/상태 포인트 형식을 사용한다. Journey의 QANDA형 evidence board와 수업 worksheet는 서로 보완한다.
- 개인 사용 경험에서 도출한 우선순위가 review의 가장 잦은 문제와 다른 이유를 설명한다. 리뷰 저점은 Sync, 개인 과업 저점은 Outlook이다.
- 5 Why의 뒤 단계는 UX 가설이다. Wallet 내부 architecture나 의도에 대한 조사 결과로 쓰지 않는다.
- 사용자가 직접 보고한 iPhone 14 Pro Max/Wallet 5.7.5는 기록했으나 정확한 iOS 숫자와 실제 조작 위치·시간은 없다.
- 새로 보완한 판단은 assistant 위임 작성으로 표시한다. 조사 참여자·인용·성과·리허설 기록을 만들어내지 않는다.
- 소스 code와 screenshot·deck의 최종 수치는 같아야 한다. 급여가 목표일을 넘기는 시나리오와 현재/예상 상태를 구분한다.
- 웹 넓은 viewport 검증을 native desktop 앱 실행 증거로 부르지 않는다. 실제 재무/AI 기능을 구현한 것처럼 시연하지 않는다.
- 디자인의 자연스러움은 작성자를 증명하지 않는다. 발표자가 선택 이유와 근거의 한계를 자기 말로 설명하는 것이 핵심이다.

정량 UX 성과·사용자 시험 결과는 없다. 다음 검증 질문은 사용자가 현재/예상·포함/제외 항목을 구분하고, 목표일을 넘는 수입 지연의 의미를 설명할 수 있는가이다.
