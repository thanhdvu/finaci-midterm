# 원칙 카드 — finaci v2

> 수업 5칸 형식: 원칙 · 근거 · 적용 · 시연 · 판단. P번호는 디자인 가이드/코드와 같이 사용한다. 근거의 종류(사용자 경험, 화면 관찰, review)는 서로 대체하지 않는다.

### 원칙 카드 P07

| 칸 | 내용 |
|---|---|
| **원칙** | Nielsen 7 — 유연성과 효율성: 자주 하는 작업을 빠르게 하고 반복 입력을 줄인다. |
| **근거** | 학생은 이미 등록한 Planned Payment를 Outlook에서 보려면 다시 입력해야 했다고 보고했다 (`prompt-log.md` L018–L020). 이는 개인 관찰이다. R01–R20 중 이 흐름을 직접 다룬 review는 없다. |
| **적용** | 화면 A `A-5` 및 화면 B `B-3`: 등록된 반복 항목을 날짜·이름·금액·통화와 함께 표시한다. 구현은 GET 응답 표시만 한다. Flutter 위젯명은 `CustomScrollView`/`ListTile` (A), `ListView`/`Card` (B); P07 추적 주석을 확인한다. |
| **시연** | A → “일정 자세히 보기” → B. 동일한 예정 항목이 두 화면에 보이는지 실제 실행 캡처/데모로 확인한다. 실행 캡처는 `docs/screenshots/finaci-a.png`와 `finaci-b.png`에 있다. |
| **판단** | 모든 계좌 동기화나 자동 입력은 만들지 않는다. 범위를 반복 예정 항목 재사용으로 좁힌다. 이는 수업의 UI-only 범위에 맞고, 제휴/동기화 안정성을 해결했다고 주장하지 않는다. |

### 원칙 카드 P06

| 칸 | 내용 |
|---|---|
| **원칙** | Nielsen 6 — 기억보다 재인: 이미 알고 있거나 입력한 정보를 다시 기억·입력하게 하지 않는다. |
| **근거** | 학생의 설명에 따르면 Planned Payments와 Outlook은 분리되어 있고 Outlook에 반영하려면 다시 입력한다 (`prompt-log.md` L020). P06은 P07을 보조한다. Review 근거가 아니라 개인 경험이다. |
| **적용** | `A-5`/`B-3`에 반복 예정 항목을 같은 이름·날짜·금액으로 보이고, `반복 예정 항목` 출처를 표시한다. 사용자는 어느 항목이 전망에 포함되는지 알아볼 수 있다. |
| **시연** | A/B에서 항목명을 대조한다. JSON 고정 데이터이며 사용자가 추가한 거래를 저장/재사용하지 않는다. 실행 캡처는 A/B와 `docs/screenshots/states/`에 저장했다. |
| **판단** | 별도의 두 번째 입력 양식을 만들지 않고 같은 GET 데이터의 표현을 재사용한다. 대안인 실시간 자동 연결은 과제 범위 밖이며, bank integration의 가용성도 확인하지 않았다. |

### 원칙 카드 P01

| 칸 | 내용 |
|---|---|
| **원칙** | Nielsen 1 — 시스템 상태의 가시성: 사용자는 현재 상태와 예상 상태, 진행 상황을 알 수 있어야 한다. |
| **근거** | 학생은 Wallet의 Outlook이 어렵고 이미 입력된 계획이 반영된 미래 상황을 스스로 계산해야 했다고 보고했다 (L019–L020). 이는 리뷰 R01–R20의 직접 근거가 아니다. |
| **적용** | A-3/A-4/B-2/B-6에서 실제·예상, 목표 날짜, 기간, 날짜별 정적 예시를 구분한다. A-6/B-5는 포함·제외 조건을 가까이 둔다. |
| **시연** | A의 예상 흐름과 B의 예정 항목을 열어 날짜/금액/전망 범위를 확인한다. UI에 “예시 데이터”와 고정 mock 범위를 표시한다. |
| **판단** | 확정 잔액처럼 단정하는 대신 “예상”으로 표현한다. 실제 결과와 달라질 수 있는 변동 지출·급여 시점·환율은 전망에 포함하지 않는다. L046의 위임 보완 판단은 라벨만으로 부족하다고 보아, 고정 예시 전망·반영/제외 항목·기준일·예시 환율과 목표일을 넘는 급여 지연 사례를 함께 제시한다. |

### 원칙 카드 P05

| 칸 | 내용 |
|---|---|
| **원칙** | Nielsen 5 — 오류 예방: 고정 전망 예시를 보장 잔액으로 읽는 실수를 예방한다. |
| **근거** | L046에서 전체 감사를 위임받아 자체 검토했다. 목표일까지의 긴 전망은 제외된 변동 지출·환율·급여 지연 때문에 실제와 달라질 수 있다. 직접 대응 review나 측정된 오해 사례는 없다. |
| **적용** | A-3/A-4는 현재·예상을 분리한다. A-6/B-5는 기준일·고정 환율·반영/제외 항목을 전망 가까이에 표시한다. C-3/C-5는 목표일 이후로 지연된 급여 예시와 전제를 보여 준다. |
| **시연** | 기본 2/28 예시 ₩3,135,000과 2/25 급여가 3/4로 늦어진 경우 ₩2,755,000을 비교한다. 앱 계산 결과가 아닌 사전 작성 예시임을 확인한다. |
| **판단** | 수정. 예상 라벨 하나에 의존하지 않고 출처·제외 조건·목표일을 넘는 사례를 추가한다. 사용자 오해 감소는 향후 검증한다. |

### 원칙 카드 P10

| 칸 | 내용 |
|---|---|
| **원칙** | Nielsen 10 — 도움말과 문서: 기능의 목적, 가정, 한계를 이해하도록 돕는다. |
| **근거** | Finaci의 C 화면은 “급여가 7일 늦으면?”이라는 상황을 미리 작성한 응답으로 보여 준다. 실제 AI나 재무 조언이 아니다. |
| **적용** | C-4/C-5: 사전 작성 예시 응답, 가정, 제외 항목과 “실제 AI/재무 조언 아님” 안내를 보여 준다. |
| **시연** | A 또는 B에서 C BottomSheet를 연다. 응답이 미리 정해져 있고 닫을 수 있음을 보여 준다. |
| **판단** | 실제 LLM·외부 API 연결은 제외한다. 사용자는 설명 시나리오만 미리 볼 수 있고, 이 결과를 실제 개인 상황에 맞춘 조언으로 표시하지 않는다. |

- 각 “적용”의 Flutter element ID: `docs/디자인가이드.md` 표와 코드 주석을 맞춘다.
- 전·후 시연은 실제 Flutter 실행 캡처 `docs/screenshots/finaci-*.png`, 상태 캡처 `docs/screenshots/states/`와 Wallet 캡처 `docs/screenshots/journey/`를 사용한다. 각 캡처의 변경 전후 맥락은 `docs/셀프논증.md`에 기록했다.
