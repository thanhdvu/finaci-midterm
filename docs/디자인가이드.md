# 디자인 가이드 — finaci v2

> 기획 5단계 화면 기획 및 Flutter 구현 대조표. 수업 템플릿의 형식과 P번호를 따른다. 코드와 요소 번호를 함께 검토하고, 수업 범위에 맞게 UI만 만든다.
> 대상은 글로벌 이용자이며, 프로토타입 상황은 KRW와 VND를 함께 쓰는 한국 거주 베트남 유학생이다. 금액·환율·AI 응답은 모두 예시 데이터다.

### finaci visual identity

- 브랜드 성격은 차분하고 친근하며 믿음직한 금융 동반자다. `finaci`는 항상 소문자로 쓴다.
- 색상은 따뜻한 아이보리 `#F7F4EC`, 차콜 `#292D27`, 딥 올리브 `#4F5B3A`, 세이지 `#E5E9DC`, 테라코타 `#B5674C`, 웜 스톤 `#DCD7CB`를 사용한다. 작은 글자/아이콘의 테라코타는 대비를 위해 `#8F4D3A`로 어둡게 쓰고, 보조 텍스트도 대비가 확보된 차콜 계열로 쓴다. 파란색 계열은 제거한다.
- 기존 Finaci 리본 캐릭터의 `explaining` 포즈는 설명 범위(A-6)와 미리 작성된 시나리오 응답(C-4)에만 둔다. 핵심 금액·조건보다 앞서지 않게 작은 안내 역할로 제한한다.
- Flutter asset: `assets/mascot/finaci-explaining.png`; 출처는 이전 Finaci 프로젝트의 `frontend/public/mascot/explaining.png`. 출처 파일은 사용자 제공 프로젝트 폴더에서 복사했다. 제작자/라이선스는 README에 별도 확인 대상으로 기록한다.

## 1. 화면 목록과 흐름

| 화면 | 비즈니스 명칭 | Flutter 파일 | 진입 방식 | GET |
|---|---|---|---|---|
| A | 현금흐름 홈 | `lib/screens/a_list_screen.dart` | 첫 화면 | `/outlook` |
| B | 현금흐름 일정 상세 | `lib/screens/b_detail_screen.dart` | 쌓기(push) — A의 “일정 자세히 보기” | `/plannedPayments`, `/outlook` |
| C | 급여 지연 시나리오(예시) | `lib/screens/c_result_sheet.dart` | 덮기(modal) — A 또는 B의 “상황 비교” | 없음 · 미리 정한 임의 응답 |
| D | 빠른 기록 | `lib/screens/d_quick_add_sheet.dart` | 덮기(modal) — A/B 중앙 + | 없음 · 입력값은 저장하지 않음 |

```
A 현금흐름 홈 ── 쌓기(push) ──▶ B 현금흐름 일정 상세
       └──────── 덮기(modal) ──▶ C 급여 지연 시나리오(예시)
A/B 중앙 + ───── 덮기(modal) ──▶ D 빠른 기록(예시)
B 일정 상세: 기간 탭(7일 · 30일 · 목표일까지). A의 기본 전망 범위는 목표일.
```

- `json-server`는 읽기 전용 GET만 사용한다. `/outlook`은 미리 작성한 시점별 전망과 목표 카드 예시, `/plannedPayments`는 이미 입력된 반복 수입·지출 예시를 반환한다.
- 실제 환율 변환, 잔액 예측, 목표 계산, 외부 AI 호출, 저장은 구현하지 않는다. 화면에 보이는 값은 `db.json`에 준비한 고정 데모 값이다.
- 적응형: 창 너비에 따라 A는 760dp부터 전망/보조 정보를 2열로 배치한다. 계좌 영역은 가용 폭 320dp부터 2열, 760dp부터 3열이다. 2열에서는 계좌 추가 타일을 한 줄 전체로 보여 빈 반쪽 칸을 줄인다. B는 760dp부터 항목 목록과 전망 안내를 나란히 둔다. 모바일 바깥 여백과 카드 안쪽 여백은 16dp, 카드 간격은 12dp, 마지막 콘텐츠 여백은 24dp다.

### Flutter 레이아웃 근거

- 각 화면은 `Scaffold`와 `AppBar`로 기본 구조를 세우고, `Card`, `ListTile`, `SegmentedButton`, `TabBar`, `FilterChip` 등 수업 위젯으로 정보를 묶는다. A/B는 공통 `NavigationBar`를 두어 Dashboard·Planning·추가·Statistics·More를 보여 준다. 중앙 +는 같은 빠른 기록 BottomSheet D를 열고, Statistics/More는 범위 안내 SnackBar를 보여 준다.
- A는 `CustomScrollView`로 세로 콘텐츠를 스크롤하고, `LayoutBuilder`의 실제 `maxWidth`를 읽어 `Row`/`Column` 배치를 바꾼다. 고정 기기명이나 방향값으로 분기하지 않는다.
- B는 `DefaultTabController`와 `TabBarView`로 기간을 전환하며, 목록은 부모 `ListView`가 스크롤한다. C는 `showModalBottomSheet` 안에서 `SingleChildScrollView`를 사용해 작은 화면에서도 내용을 읽을 수 있게 한다.
- 여백과 모서리는 `ThemeData`의 Material 3 테마를 공통 사용한다. 한국어 글리프가 기기/브라우저 폰트에 의존하지 않게 `ThemeData(fontFamily: 'NotoSansKR')`와 번들된 Noto Sans KR을 쓴다. 그래프는 수업 범위에 맞게 JSON의 정적 높이로 그린 `Row`/`Container` 막대이며, 실행 중 계산하지 않는다.

### 디자인 가이드 글 — 예정 항목 재사용

- **목적:** 사용자가 Planned Payments에 등록한 고정 수입·지출을 현금흐름 전망에서도 다시 입력하지 않고 확인한다.
- **내용:** A-5와 B-3에 날짜, 항목명, 입출금 유형, 원 통화 금액, 등록 출처를 보여 준다. A-6/B-5는 포함/제외 기준을 설명한다.
- **의도:** 입력 반복을 줄이고 알려진 데이터를 알아보게 한다(P07 주요, P06 보조). 예측이 실제 값처럼 보이지 않도록 현재/예상 상태와 제외 항목도 함께 둔다(P01/P05).

### 디자인 가이드 글 — 저축 목표 요약

- **목적:** 목표를 별도 계산 기능처럼 추가하지 않고, 현금흐름을 왜 확인하는지 보여 주는 보조 use case다.
- **내용:** A-7은 예시 목표 1개, 통화가 분명한 현재/목표 금액, 기한, 미리 작성한 필요 저축액을 보여 준다. 값은 고정 mock data이며 산식은 실행하지 않는다.
- **의도:** 목표와 전망의 관계를 짧게 드러내되, 핵심 문제인 예정 항목 재사용/미래 현금흐름보다 시각적 우선순위를 낮춘다(P01/P02/P08).

### 디자인 가이드 글 — 정적 전망 예시

- **목적:** 사용자가 앞으로의 잔액 흐름을 검토할 수 있는 화면 구조를 시연한다.
- **내용:** A-4/B-6은 미리 정해둔 날짜별 예시를 보인다. 실제 환율·잔액 계산·AI 호출은 하지 않으며, C-4/C-5에 범위와 가정을 고지한다.
- **의도:** 로그 나열을 넘어 계획에 필요한 정보를 보여 주되, 실제 재무 예측으로 오인되지 않게 한다(P01/P10).

## 6. 화면 D — 빠른 기록(예시 BottomSheet)

정보 순서: **거래 종류 → 금액 → 계좌·통화 → 분류 → 날짜 → 확인**. A/B의 Wallet형 중앙 +에서 같은 sheet를 연다.

| 번호 | Flutter 위젯명 | 비즈니스 명칭 | 정보 전달 기준 | 원칙 | 편의성 포인트 |
|---|---|---|---|---|---|
| D-1 | `SegmentedButton` | 지출 · 수입 · 이체 | 한 번에 하나의 거래 종류를 선택 | P07 | 입력 맥락을 먼저 정해 불필요한 필드를 줄임 |
| D-2 | `TextField` | 금액 | 숫자 키보드와 선택 통화 기호를 표시 | P02 | 핵심 입력이 첫 화면에 바로 보임 |
| D-3 | `ChoiceChip` | 한국 계좌 · 베트남 계좌 | 계좌 예시와 KRW/VND를 함께 표시 | P02 · P06 | 입력 중 통화를 알아보고 바꿀 수 있음 |
| D-4 | `ChoiceChip` | 분류 | 거래 종류에 맞는 예시 분류만 표시 | P07 | 짧은 선택으로 기록 입력을 이어감 |
| D-5 | `Card` + `ListTile` | 날짜 | 현재 선택값은 “오늘”로 표시 | P02 | 저장 전에 기록 날짜를 확인 |
| D-6 | `FilledButton` + `SnackBar` | 기록 추가 예시 | 버튼은 입력 예시를 닫고 저장되지 않았다는 메시지만 표시 | P01 · P10 | 피드백은 제공하되 실제 거래·저장은 만들지 않음 |

- **목적:** Wallet에서 편리했던 중앙 + 진입을 활용해 어느 주요 탭에서도 한곳에서 입력 폼을 열게 한다.
- **범위:** 지출/수입/이체, KRW/VND 계좌, 분류, 날짜를 보여 주는 수업용 UI다. 텍스트 입력과 선택은 화면 안에서만 바뀐다. 기록 추가 버튼은 SnackBar 예시만 띄우며 GET 외 API, 거래 계산, 영구 저장을 하지 않는다.
- **Flutter 근거:** `showModalBottomSheet`와 `SingleChildScrollView`로 기존 화면 맥락을 유지하고 작은 화면/키보드에서도 내용을 스크롤한다. `SegmentedButton`, `TextField`, `ChoiceChip`, `ListTile`, `FilledButton`은 수업에서 다룬 기본 위젯을 사용한다.

## 7. 상태관리 포인트 — 표시만, 실제 구현하지 않음

| 바뀌는 데이터 | 어디서 바뀌나 | 보이는 곳(화면 · 요소) | 코드 주석 |
|---|---|---|---|
| 실제/예상 보기 | A-3 탭 | A-3 선택 스타일, A-4 그래프 제목 | `// STATE: 보기 모드 → A-3, A-4` |
| 전망 JSON 데이터(목표 카드 포함) | GET `/outlook` | A-4, A-7에 정적 값 표시 | 선택/저장 상태는 구현하지 않음 |
| 선택 기간(7일/30일/목표일까지) | B-2 탭 | B-2 선택 상태, B-3/B-6 범위 | `// STATE: 전망 기간 → B-2, B-3, B-6` |
| 수입/지출 필터 | B-4 칩 | B-3 항목 목록 | `// STATE: 항목 필터 → B-4, B-3` |
| GET 결과 상태(loading/error/empty/data) | A-10 / B-7 | 해당 화면 상태 위젯 | `// STATE: GET 상태 → A-10 또는 B-7` |
| BottomSheet 표시 여부 | A-9 / B-8 버튼 · C-1 닫기 | C 전체 | `// STATE: 시나리오 시트 → C-1~C-5` |
| 빠른 기록 종류·통화·분류 선택 | D-1 / D-3 / D-4 칩 | D 입력 폼의 선택 표시 | `// STATE: 빠른 기록 선택 → D-1, D-3, D-4` |
| 입력 금액 | D-2 TextField | 입력 칸에만 표시 | 영구 저장이나 계산은 하지 않음 |
| BottomSheet 표시 여부 | A/B 중앙 + · D 닫기/기록 추가 | D 전체; 추가 버튼 뒤에는 미저장 안내 | `// STATE: 빠른 기록 시트 → D-1~D-6` |
| 현재 화면 경로 | A/B 이동과 뒤로 가기 | A-11 / B-9 선택 표시 | `// STATE: 현재 경로 → NavigationBar 선택` |

> Flutter 코드에는 위 데이터 흐름을 `// STATE:` 주석으로만 표시한다. Provider/Riverpod/Bloc이나 영구 저장은 사용하지 않는다. 화면 안의 토글/탭/filter는 허용된 `setState`만 사용한다.
