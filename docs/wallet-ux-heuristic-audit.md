# Wallet 휴리스틱 검토

Wallet iOS5.7.5의 실제 화면, 개인 경험, 공개 리뷰를 구분한 검토다. 모든 P번호를 위반 판정으로 쓰지 않는다. 핵심은 재입력에 대한 P07과 P06이다.

| 원칙 | 화면에서 확인한 장점/질문 | 판단 범위 |
|---|---|---|
| P01 시스템 상태의 가시성 | 잔액·예산 사용률·날짜가 표시된다. Outlook에 어떤 항목이 반영됐는지 사용자가 알 수 있는가? | 표시 존재는 관찰. 결과의 근거 이해는 개인 어려움이다. |
| P02 실세계와의 일치 | 계좌·통화·수입·지출·이체를 구분한다. | 다중 통화 지원은 장점이다. Wallet에 해당 기능이 없다고 쓰지 않는다. |
| P03 사용자 제어와 자유 | Cancel/Back, 필터와 입력 유형을 제공한다. | 환불·삭제·되돌리기의 전체 흐름은 시험하지 않았다. |
| P04 일관성과 표준 | 하단 탐색과 중앙 +, 목록형 입력 패턴이 반복된다. | finaci에 유지할 패턴이다. 과거 R08은 현재 변경 비교 증거가 아니다. |
| P05 오류 예방 | Required 입력 안내가 있다. | Sync 중복 보고는 과거 리뷰이며 현재 재현하지 않았다. |
| P06 기억보다 재인 | 계좌 카드와 차트가 상황을 보이게 한다. | Planned Payments가 Outlook의 근거로 연결되지 않아 기억/연결 부담이 있었다는 개인 경험. 보조 원칙으로 채택했다. |
| P07 유연성과 효율성 | 중앙 +와 Templates가 반복 입력을 줄이는 장점이다. | 예정 항목을 Outlook에 다시 입력한 개인 과업의 주원칙으로 채택했다. |
| P08 미적·최소주의 디자인 | 모듈과 통계를 제공한다. R13/R15는 복잡성을 언급한다. | 화면 항목이 많다는 이유만으로 나쁜 UX라고 단정하지 않는다. Android 리뷰를 iOS에 일반화하지 않는다. |
| P09 오류 인식·진단·복구 | 수기 입력 등 대안이 보인다. 과거 연결/중복 불만이 있다. | 실제 연결 오류와 복구 상태는 시험하지 않았다. |
| P10 도움말과 문서 | 공식 Help Center와 입력 안내가 있다. | 국가별 연결과 전망 가정을 설명하는 finaci 안내에 활용한다. |

## 우선 문제와 근거

사용자는 Planned Payments의 항목을 Outlook에서 보려면 재입력해야 했다고 확인했다. P07은 반복 조작 감소, P06은 이미 있는 항목을 결과 근거로 알아보게 하는 기준이다. 내부 backend가 데이터를 공유하지 않는다고 단정하지 않는다.

finaci는 계좌 카드·중앙 +·탭·예정 항목의 장점을 유지하고 같은 이름/날짜/통화의 항목을 A/B에서 연결한다. 숫자 곁에 기준일·예시 환율·포함/제외를 두어 P01/P10을 보완한다. 실제 계산은 하지 않는다.

## 추가 검토가 필요한 질문

- Outlook의 상세 기능과 계정/버전별 차이는 무엇인가?
- 월초 잔액이나 예정 항목을 사용자가 바로 설명할 수 있는가?
- Templates가 입력 시간이나 터치 수를 실제로 줄이는가?
- 실제 연결 실패 시 원인과 대안을 이해할 수 있는가?

현재는 개인 회고 평가와 화면 분석이다. 소요 시간·완료율·다수 사용자 평가는 없다. 공개 리뷰의 유효성 대조는 `wallet-review-notes.md`, 원칙 적용의 최종 카드와 코드는 `원칙카드.md`와 `lib/`에서 확인한다.
