# finaci 발표 대본 — 자연스럽게 설명하는 6분

목표 시간이며 실제 리허설 기록은 아니다. 괄호는 행동 지시로 읽지 않는다. 숫자와 위젯명을 전부 읽지 말고, 선택의 이유를 설명한다. 영상 약1분은 전체6분 안에 포함한다.

## 시작 — 1–3장

안녕하세요. 오늘 소개할 finaci는 여러 나라와 통화에 걸쳐 돈을 관리하는 사람을 위한 앱입니다.

제가 이 문제에 관심을 가진 이유는 제 수입이 한곳에서, 한 통화로 들어오지 않기 때문입니다. 베트남에서 받는 원격 급여도 있고, 한국에서 받는 아르바이트 급여도 있습니다. 잔액은 각각 확인할 수 있는데, 다음에 돈이 들어오기 전에 어떤 비용을 낼 수 있는지는 따로 생각해야 했습니다.

그래서 저는 ‘얼마를 썼는가’ 다음에 ‘앞으로 어떤 상태가 되는가’를 볼 수 있으면 좋겠다고 생각했습니다. 다만 finaci의 대상을 베트남과 한국으로 제한한 것은 아닙니다. 이번 시연에서는 제 상황을 설명하기 쉬운 VND와 KRW를 예시 데이터로 골랐습니다.

## 현행을 보며 고른 문제 — 4–6장

참조 앱은 Wallet입니다. 직접 써 보니 계좌별 잔액을 나눠 보는 구조와 중앙 플러스 버튼은 편리했습니다. 이런 장점은 유지하고 싶었습니다. Wallet에도 이미 여러 통화와 예정 결제 기능이 있으므로, 단순히 통화를 두 개 보여 주는 것만으로 개선이라고 말할 수는 없습니다.

공개 리뷰20개도 함께 봤습니다. 연결과 동기화에 대한 불만이 눈에 띄었지만, 서로 다른 지역과 플랫폼의 리뷰이기 때문에 지금의 iOS에서도 똑같이 발생한다고 판단하지는 않았습니다.

제 경우에는 등록한 Planned Payment를 Outlook에서 확인하려다 다시 입력하는 흐름이 더 직접적인 문제였습니다. 여기서 고민이 있었습니다. 불만이 많은 Sync부터 고쳐야 할까, 아니면 제가 실제로 겪은 과업을 고쳐야 할까 하는 점입니다.

저는 이번 과제에서는 재입력을 골랐습니다. 은행 제휴를 넓히는 일보다, 이미 있는 정보를 화면에서 어떻게 연결할지 제가 더 구체적으로 설명하고 바꿀 수 있기 때문입니다. 이것이 모든 사용자에게 가장 큰 문제라는 뜻은 아닙니다. 저니와5Why에서도 이 판단의 범위를 적었습니다.

## 설계와 반론 — 7–8장

(전망 숫자와 그 아래 예정 항목을 차례로 가리킨다.)

이 화면에서 제가 중요하게 본 것은 그래프 자체보다, 숫자가 어디서 왔는지 확인할 수 있는가입니다. 홈에서 흐름을 보고, 일정 화면에서는 같은 예정 항목의 날짜와 통화를 확인합니다. 다시 입력하는 폼을 하나 더 만드는 대신, 같은 정보를 두 맥락에서 보여 주는 방향입니다. P07을 우선하고 P06을 보조로 고른 이유도 여기에 있습니다.

목표 카드는 작은 보조 정보로 남겼습니다. 학비도 목표의 하나지만, 여행비나 비상금처럼 다른 목적에도 같은 흐름을 사용할 수 있어야 하기 때문입니다. 이번 사례는 기한이 있으므로 목표일까지를 기본으로 두고, 짧게 확인할 사람에게는7일과30일도 남겼습니다.

AI에게 반론을 요청하면서는 다른 문제가 드러났습니다. 입력을 재사용한다고 해서 미래 숫자가 믿을 만해지는 것은 아니라는 점입니다. 처음의 ‘예상’ 표시만으로 사용자가 안심할 수도 있습니다.

그래서 숫자 가까이에 기준일과 환율 가정, 포함하지 않은 변동 지출을 붙였습니다. 또 급여가7일 늦는다는 말만으로 결과를 바꾸지 않고, 실제로 목표일을 넘겨 들어오는 경우로 예시를 수정했습니다. 기능의 범위는 유지하되, 사용자가 해석하는 방식은 수정한 결정입니다.

## 구현 — 9장

구현에서도 이 정보 구조를 그대로 옮기려고 했습니다. 홈에서 일정으로 가는 것은 Navigator, 기간 선택은 TabBar, 상황 비교와 빠른 기록은 BottomSheet입니다. 새 구조를 많이 추가하기보다 수업에서 다룬 기본 위젯으로 설명 가능한 구성을 선택했습니다.

데이터는 json-server에서 GET으로만 읽습니다. 로딩, 오류와 재시도, 빈 화면을 따로 만들었고 창 너비에 따라 배치를 바꿉니다. 실제 환율 변환이나 예측 계산, 저장, AI 호출은 없습니다. 이 과제에서 검증하려는 것은 ‘숫자를 계산하는 능력’보다 ‘계산의 전제와 근거를 읽게 하는 화면’입니다.

## 영상 — 10장

(영상 재생 전에 약10초.)

이제 약1분 영상으로 보시겠습니다. VND와 KRW는 이번 사례의 데이터이고, 앱의 전체 대상은 다중 통화 사용자입니다. 홈의 전망에서 일정의 근거로 연결되는 부분을 봐 주시면 좋겠습니다.

(약1분 영상을 재생한다. 조작을 다시 설명하지 않고 필요한 때 짧게 한 문장만 덧붙인다.)

- 일정이 보일 때: “여기서 같은 예정 항목을 다시 확인할 수 있습니다.”
- 지연 비교 때: “입금이 목표일 뒤로 넘어가는 조건입니다.”
- 빠른 기록 때: “통화 선택은 화면 표시만 바뀌고 저장되지는 않습니다.”

(영상이 끝나면 다음 장으로 이동한다. PDF에서는 포스터/영상 링크 또는 웹 데모를 연다.)

## 마무리 — 11장

이번에 배운 것은 정보가 이미 있다는 것과, 그 정보로 결정을 내리기 쉽다는 것은 다르다는 점입니다. 다음에는 사용자가 전망의 한계를 이해하는지, 반영된 항목을 스스로 설명할 수 있는지 확인하고 싶습니다. 감사합니다.

## 예상 질문 — 외워 읽기보다 핵심만 기억

| 질문 | 자연스러운 답변 핵심 |
|---|---|
| 한국·베트남 전용 아닌가요? | 그 조합은 제 과업을 설명하는 샘플입니다. 제품 대상은 다중 통화 이용자입니다. 빠른 기록은 KRW/VND/USD/EUR/JPY 예시 선택을 두었습니다. 다른 국가의 사용성까지 검증했다고 말하지는 않습니다. |

| Sync 리뷰가 더 많은데 왜 다른 문제를 골랐나요? | 리뷰 빈도와 제 과업 우선순위를 구분했습니다. 이번 UI 과제에서 직접 경험과 개선 가능성을 근거로 재입력을 선택했습니다. |
| 미래 금액은 실제인가요? | 고정 예시입니다. 급여가 목표일을 넘는 상황의 의미를 보여 주며 실행 중 재무 계산은 하지 않습니다. |
| AI가 다 만든 것 아닌가요? | 코드와 문장 정리에 AI를 활용했고 반론과 추가 작성 부분도 기록했습니다. 제 경험과 주요 선택, 공개 리뷰, 가설을 구분했으며 제가 왜 선택했는지 설명하는 것이 이 발표의 핵심입니다. |
