# Fishbone와 5 Why

사용자는 2026-10-28 UX 원인 후보를 채택했다. 2026-10-29 L046에서 논리를 보완했다. 내부 기술 원인은 조사하지 않았다.

## 분석 문제

사용자는 Wallet iOS5.7.5에서 Planned Payments를 별도로 관리하고, Outlook에서 확인하려면 같은 항목을 다시 입력해야 했다고 보고했다. 이미 있는 반복 항목으로 미래의 상황을 이해하려는 과업이 대상이다. 월 예산 시작일 문제는 관련된 별도 관찰이다.

리뷰 최저점은 Sync이고 개인 과업 최저점은 Outlook이다. 직접 경험과 UI 개선 가능성 때문에 후자를 선택했다. R01–R20이 Outlook 재입력을 직접 증명한다고 쓰지 않는다.

## Fishbone의 여섯 시각

| 시각 | 가능한 원인 | 근거와 미확인 부분 |
|---|---|---|
| 모바일 UX | 잔액·반복 항목·전망이 다른 화면에 있어 맥락 전환이 필요하다. | 화면 구분은 캡처로 확인. 탭 수/시간은 측정하지 않았다. |
| 사용성 | 사용자 경험상 Planned Payments를 Outlook에 재입력한다. | 직접 보고한 과업. 다른 계정/버전에서 재현하지 않았다. |
| 데이터 | 전망에는 여러 계좌·통화·예정일과 예정/실제 구분이 필요하다. | KRW/VND와 예정 항목은 관찰했다. Outlook의 내부 식과 환율은 미확인이다. |
| API | 국가·제휴기관별로 자동 연결 범위가 달라질 수 있다. | 국가별 목록만 확인했다. 실제 연결은 시험하지 않았다. 핵심 원인으로 택하지 않았다. |
| 네트워크 | 연결 실패/중복/지연은 잔액 신뢰에 영향을 줄 수 있다. | R06/R09/R10/R18/R20의 과거·다지역 보고. 현재 iOS 재현 증거는 없다. |
| 프로세스 | 반복 수입·지출을 넣어도 사용자가 계획을 직접 연결한다. 월 시작일 조정도 어려웠다. | 직접 경험한 절차다. Wallet의 설계 의도나 내부 원인은 미확인이다. |

Bank Sync의 국가별 제휴 범위는 보조 맥락이다. 사용자는 partnership 성격이 강하다는 이유로 주된 UX 과업에서 제외했다.

## 5 Why의 연결

| 질문 | 설명 | 근거 수준 |
|---|---|---|
| 1. 목표일의 상황을 답하기 어려운 이유는? | 이미 아는 수입·지출을 Outlook과 직접 연결해야 한다. | 사용자의 경험 설명 |
| 2. 이미 아는 항목을 다시 연결하는 이유는? | Planned Payments에 있는 항목도 Outlook에서 보려면 다시 입력했다고 보고했다. | L029–L030의 직접 확인 |
| 3. 재사용 관계를 알아보기 어려운 이유는? | 항목의 출처·날짜·통화·반영 상태와 결과의 연결이 사용자가 시험한 흐름에서 드러나지 않았다. | 경험/화면에 대한 UX 해석 |
| 4. 연결이 끊겨 있다고 느끼는 이유는? | 기록과 전망이 별도 과업처럼 느껴져 계획을 완성하는 연결 단계가 부족하다. | 경험 조직에 관한 UX 가설 |
| 5. 입력한 항목에서 계획까지 완결되지 않는 이유는? | 등록 항목을 예상 결과에서 인지하고 역으로 확인할 수 있는 연결이 부족하다는 UX 원인을 제안한다. | UX 원인 후보. 기술 원인은 미확인 |

뒤 단계는 Wallet 제작자의 의도를 조사한 사실이 아니다. 같은 증상을 반복해서 원인이라고 쓰지 않고, 항목의 근거를 추적할 수 있는가로 논리를 좁혔다.

## 채택한 결론과 화면으로의 연결

- 확인한 증상: Planned Payments와 Outlook 사이에 재입력이 필요했다는 개인 경험.
- UX 원인: 이미 입력한 예정 항목을 전망의 근거로 인식하고 재사용하는 연결 부족.
- A-5/B-3은 항목의 이름·날짜·통화를 일치시킨다. A-6/B-5는 포함/제외 항목, A-4/B-6은 현재/예상을 구분한다.
- 기간별 결과는 고정 예시다. 실제 계산·추천 알고리즘이나 AI 호출은 구현하지 않는다.
- P07을 주원칙, P06을 보조로 채택했다. 내부 구조의 결함이나 모든 Wallet 사용자의 문제라고 단정하지 않는다.
