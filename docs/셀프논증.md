# 셀프 논증 기록 — finaci v2

> L017–L043의 선택은 실제 대화를 요약했다. 2026-10-29 전체 감사에서 사용자는 남은 설계 판단의 작성도 보조자에게 위임했다(L046). 새 판단은 **위임 보완**으로 표시하고 과거 학생 발언으로 소급하지 않는다. 반론·재반론은 요약문이다.

## 쟁점 1 — 어떤 문제를 먼저 개선할까?

| 단계 | 기록 |
|---|---|
| 내 주장 | 이미 입력한 Planned Payments를 Outlook에서 다시 입력해야 했던 흐름을 우선 개선한다. |
| AI 반론 | 표본에서 연결·동기화 불만이 더 많이 나타난다. 리뷰 수로 보면 Bank Sync가 우선이다. |
| 자체 점검 반론 (위임 보완) | 개인 경험을 모든 사용자의 결함으로 넓히거나, Outlook 내부 동작을 확인한 것처럼 말하면 근거가 약해진다. |
| 재반론·수정 | 학생은 은행 범위가 시장·제휴에 좌우된다고 보고, 직접 겪은 입력 반복을 골랐다. 이번 제안은 관찰한 iOS 5.7.5의 과업에 한정한다. 공개 리뷰와 개인 경험을 구분한다. |
| 결론 | **유지**. 과업 관련성·직접 관찰·UI 과제 범위를 기준으로 입력 반복을 우선한다. Sync는 별도 관찰로 남긴다. |
| 근거 | L017–L020, L029–L030, L035. P07 주요, P06 보조. R11(입력 부담), R03(잔액 가시성)은 인접 근거다. Outlook 재입력 직접 리뷰는 없다. |
| 전·후 | 전: `docs/screenshots/journey/wallet-planned-payments-redacted.jpg` + `wallet-statistics-redacted.jpg`. 후: `docs/screenshots/finaci-a.png` + `finaci-b.png`의 동일한 예정 항목·날짜·통화. |
| 추적 | 원칙 카드 P07/P06, 가이드 A-5/B-3, 코드 P번호 주석. |

## 쟁점 2 — 하단 중앙 +로 빠른 기록을 열까?

| 단계 | 기록 |
|---|---|
| 내 주장 | Wallet에서 편리했던 하단 중앙 +를 A/B에서 공통으로 사용한다. |
| AI 반론 | 기록 폼이 현금흐름보다 강조되거나 확인 버튼을 실제 저장으로 오인할 수 있다. |
| 자체 점검 반론 (위임 보완) | 여러 추가 진입을 구분하지 않으면 거래 추가인지 계좌 추가인지 모호해진다. |
| 재반론·수정 | 중앙 +는 거래용 D만 열고 계좌 추가 타일과 구분한다. D 제목과 지출/수입/이체 선택으로 맥락을 보여 준다. 확인 뒤에 저장되지 않는 예시라는 피드백을 준다. |
| 결론 | **수정**. 공통 진입을 유지하고 역할·데모 결과를 명확히 한다. |
| 근거 | L042–L043, Wallet Dashboard 캡처. P07 빠른 접근, P01/P10 상태·범위 안내. |
| 전·후 | 전: `docs/screenshots/journey/wallet-dashboard-redacted.jpg`의 중앙 +. 후: `docs/screenshots/finaci-a.png` + `finaci-d.png`; A/B에서 같은 D를 연다. |
| 추적 | 가이드 A-11/B-9/D-1–D-6, `lib/screens/d_quick_add_sheet.dart`, 카드 P07/P01/P10. |

## 쟁점 3 — 기본 기간은 30일인가, 목표일까지인가?

| 단계 | 기록 |
|---|---|
| 내 주장 | 목표가 등록된 사례에서는 목표일까지를 기본 전망 기간으로 둔다. |
| AI 반론 | 30일은 월간 생활비 주기와 맞고 간단하다. 긴 전망은 제외된 변동 지출의 영향을 키운다. |
| 자체 점검 반론 (위임 보완) | 목표 없는 사용자에게 목표일을 강요하거나, 목표 카드가 핵심 개선을 가릴 수 있다. |
| 재반론·수정 | 학생은 목표일까지를 선택했다(L039). 이번 prototype에는 목표가 있으므로 그 선택을 따른다. B에 7일/30일/목표일까지를 남기고 A의 목표 카드는 보조 위계로 둔다(L038). 목표 없는 상태는 향후 설계 과제다. |
| 결론 | **수정**. 초기 30일안에서 목표일까지로 바꾸고 짧은 기간 탭을 남긴다. |
| 근거 | L038–L039. P07 기간 전환, P01 선택 범위, P08 정보 위계. |
| 전·후 | 전: L039에 기록된 30일 설계안(실행 전 화면 없음). 후: `docs/screenshots/finaci-a.png`·`finaci-b.png`의 기본 목표일과 탭. 초기 실행 캡처를 새로 만들어 과거 증거로 쓰지 않는다. |
| 추적 | 가이드 A-4/A-7/B-2, 카드 P07/P01, `DefaultTabController(initialIndex: 2)`. |

## 쟁점 4 — 예정 항목을 재사용하면 어떤 위험이 남을까? (위임 보완)

현재 감사의 AI 검토 질문: **예정 항목을 재사용하면 어떤 위험이 남을까?** 예상 라벨만으로 신뢰성이 보장되는지를 검토했다(L046).

| 단계 | 기록 |
|---|---|
| 내 주장 | 등록된 예정 항목을 재사용하면 목표 날짜의 현금흐름을 검토할 수 있다. |
| AI 반론 | 고정 항목만으로 실제 잔액을 보장할 수 없다. 변동 지출·환율·급여 지연이 빠지면 잘못된 안심을 줄 수 있다. |
| 자체 점검 반론 (위임 보완) | 큰 미래 잔액과 목표 금액을 함께 보면 목표 달성을 확정 결과로 읽을 수 있다. 예상 한 단어만으로는 부족하다. |
| 재반론·수정 | 현재/예상을 분리하고 **고정 예시 전망**을 명시한다. 그래프 가까이에 기준일·예시 환율·포함한 반복 항목·제외한 변동 지출을 둔다. C는 급여가 목표일 뒤로 밀리는 사례를 보여 준다. |
| 결론 | **수정**. 라벨에 출처·조건·제외 항목과 목표일을 넘는 지연 사례를 더한다. 개선 효과는 향후 사용자 검증 과제다. |
| 근거 | L046의 판단 작성 위임. P01 상태 가시성, P05 오해 예방, P10 가정 설명. 대응하는 직접 store review는 없고 자체 설계 검토다. |
| 전·후 | 전: Wallet Planned Payments/Statistics. 후: A/B의 실제/예상·반영 항목 안내, C 기본/지연 비교. 강화 전 Finaci 화면의 별도 보존본이 없으므로 과거 화면을 재구성하지 않는다. |
| 고정 예시 | 기준 잔액 ₩1,615,000 = KRW ₩1,240,000 + VND ₫7,500,000의 고정 환산(₩1=₫20). 2/28 기본 예시 ₩3,135,000. 2/25 급여 ₩380,000가 7일 늦어 3/4로 가면 2/28 예시 ₩2,755,000. 값은 JSON/응답에 작성하며 앱에서 계산하지 않는다. |
| 추적 | 카드 P01/P05/P10, 가이드 A-3/A-4/A-6/B-5/B-6/C-3–C-5, `mock_server/db.json`, `lib/screens/c_result_sheet.dart`. |

## 기록의 범위

작업 시간·성공률·목표 달성률은 측정하지 않았다. 개인 경험, 공개 리뷰, 분석 가설, 고정 예시의 차이를 발표에서 설명한다. `docs/prompt-log.md`는 실제 요청과 작업의 요약이며 존재하지 않았던 대화 원문을 만들지 않는다.
